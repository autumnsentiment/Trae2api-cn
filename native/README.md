# TraeWork Native Bridge

The relay's normal Docker image is Linux and cannot load Windows PE files.
UPSTREAM_MODE=traework-native is therefore an opt-in transport that talks
to a small helper running on the Windows host where TraeWork is installed.

The helper is responsible for:

1. Loading resources/app/modules/ai-agent/ai_agent.dll and its sibling runtime
   DLLs using the TraeWork installation.
2. Connecting to the AHA `ai-agent` service through the ZeroMQ IPC address
   generated by `@aha-kit/ipc` (normally `%TEMP%\\aha\\ai-agent.sock`; the
   `40005` socket entry in `meta.json` is not the renderer's AHA wire format).
3. Sending the renderer request envelope through the `request_stream` RPC
   method described in the reverse-engineering report and client bundle.
4. Exposing an HTTP endpoint (default http://127.0.0.1:40006/v1/traework/request_stream)
   that returns native SSE events to the relay.

This repository intentionally does not redistribute proprietary TraeWork DLLs.
Set TRAE_WORK_INSTALL_DIR to the local installation (for example
E:\TRAE SOLO CN) and keep the helper on the same Windows machine. The helper
URL can be a private network address when the relay runs in Docker.

## Relay configuration

    UPSTREAM_MODE=traework-native
    TRAEWORK_NATIVE_ENABLED=true
    TRAEWORK_NATIVE_BRIDGE_URL=http://127.0.0.1:40006
    TRAEWORK_NATIVE_BRIDGE_ENDPOINT=/v1/traework/request_stream
    TRAEWORK_NATIVE_HEALTH_ENDPOINT=/healthz
    TRAE_WORK_INSTALL_DIR=E:\TRAE SOLO CN

TRAEWORK_NATIVE_ALLOW_NON_WINDOWS exists only for protocol/unit tests or an
explicitly managed Wine setup. It is false by default. If the helper is not
reachable, the relay returns a normal upstream error and does not silently
fall back to raw/remote.

## Packet contract

The relay posts one JSON object with `packet_type:"request"`, channel_id,
session_id, and params. params contains service=chat, method=chat, data, user_info,
common_params, streamlined_common_params, and client_info. The client_info
object includes connect_session_id.

The native helper uses version-1 AHA envelopes:
`{version:1,id,packet_type:"user"|"control",payload}`. The payload is a
JSON-RPC request. Streaming first returns a `streamId`, then uses
`rpc.stream.<streamId>` notifications with `meta.done`; cancellation uses
`rpc.stream.cancel.<streamId>`. The old four-byte length-prefixed TCP probe is
available only with `TRAEWORK_NATIVE_AHA_TRANSPORT=tcp-legacy` and is not a
TraeWork-compatible default.

On Windows, validate the local installation and start the helper with:

    pip install -r requirements-native.txt
    powershell -ExecutionPolicy Bypass -File tools/start_traework_native_bridge.ps1

The script reads TRAE_WORK_INSTALL_DIR, checks the expected runtime files, and
does not copy or package the DLLs.
