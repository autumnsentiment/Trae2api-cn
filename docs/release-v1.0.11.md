# Trae2api-cn v1.0.11

本版本修复调用方工具请求路由、思考强度参数传递和缓存用量统计，增加持久化的思考链路输出开关，并恢复实验性企业账号入口。

## 企业账号功能与限制

**企业级账号的权益信息可以查询和查看，但企业模型请求链路尚不完整。**

目前没有可用于联调的企业级账号，因此未完成真实企业账号的端到端验证。当前可能存在无法发起模型请求、缺失 App ID 或应用配置的情况，并可能返回：

```text
2001 failed to get app config: record not found
```

权益可见不代表模型请求已经可用，开启企业开关也不会自动补齐缺失的应用配置。本版本不宣称完整企业 SSO 或企业模型调用链路已经接通。

控制台「企业版入口」可保存选定账号并启用企业模式。启用后请求固定使用该账号和 Raw 通道，禁止失败后回退到普通账号；关闭后恢复普通路由。企业权限不能按个人 Pro 等级或积分推断，企业模式默认关闭。

## 主要更新

- 调用方携带工具定义、工具选择参数或工具历史时，自动约束到支持该协议的端点；不再因选择 Remote/Work 或失败回退而丢失工具参数。IDE/Solo 默认使用原生工具协议，保留调用 ID、参数与工具结果续轮。
- Chat、Responses、Messages 统一接收 `reasoning_effort`、`reasoning.effort`、`thinking.effort` 等写法。按当前账号与端点的实际 Trae 模型描述映射 `low`、`high`、`xhigh` 到支持的档位，不按官方同名模型推断能力；未应用的档位会在追踪信息中明确标记。
- 新增「思考链路输出」开关，可切换关键节点与上游提供的完整思考文本。设置持久保存并在启动时恢复；单次请求显式关闭仍优先。该开关只改变输出呈现，不改变模型思考强度，也不强制上游生成思考文本。
- 模型目录缓存按账号、档位、原生 function、网关和客户端身份隔离。同一范围的并发冷读取共享上游查询，避免重复请求；缓存结果独立复制，取消单个等待者不会取消其他请求。
- 保留缓存读取、缓存写入及思考 token 明细，统一传递到 Chat、Responses、Messages 和 TraeWork 输出。工具 schema 和上下文 JSON 保持稳定键序，减少等价请求的前缀变化。
- Remote 与已验证旧版 `llm_utils_chat` 的 SSE 缓存明细缺失或全零时，可按本次账号和账单 ID 补查商业账单。输入 token 必须精确匹配，旧版端点还需匹配输出 token；不重复相加账单总计与子项，不改写输入/输出总量。
- 旧版 `llm_utils_chat` 每次实际发送使用独立账单 ID，避免多轮账单累计被误归到单轮；反代逻辑会话、账号绑定和工具历史继续保留。

## 缓存与客户端说明

本次修复的是缓存统计传递与账单补查，不保证每次模型请求都命中缓存。已观察到上游 SSE 返回零、同一请求账单却有真实缓存读取；账单未就绪、超时、缺失或不匹配时保留原始计数，不伪造命中或回填历史记录。

`TRAE_CACHE_USAGE_LOOKUP_TIMEOUT_SECONDS` 默认 3 秒，最大 10 秒，设为 0 禁用。流式正文立即转发，仅最终 usage 和结束帧可能等待账单。没有可靠账单标识的端点不执行补查，账单报告缓存写入为 0 时仍保留 0。

DSH 自定义模型需要在客户端逐模型声明 `reasoningEfforts`；经 new-api 导入 API Key 或发现模型，不保证客户端自动展示 `low`、`high`、`xhigh`。DSH 0.2.0-rc.2 的自定义模型编辑器缺少此项，需要在现有 profile 中补齐或使用提供该编辑器的版本。客户端档位仍须匹配实际 Trae 描述，本版本不宣称已自动修改 DSH 主机配置。

- Docker 健康检查及源码一致性检查通过；`deepseek-v4.1-flash` 直连请求成功，同次响应记录 22,400 个缓存读取 token。该样本不代表所有请求的命中率。
